# Администрирование и защита базы данных

## Структура

`auth_user` хранит пользователей и хеши паролей. `api_note.owner_id` — обязательный внешний ключ на пользователя: один пользователь имеет много заметок. Удаление владельца с заметками блокируется `PROTECT`. В БД установлены ограничения непустого заголовка и текста. `auth_group` и `auth_user_groups` задают роль аудитора.

## Права

| Роль | Просмотр | Изменение |
| --- | --- | --- |
| Гость | Только форма входа | Запрещено |
| Пользователь | Свои заметки | CRUD своих заметок |
| Auditors | Все заметки | Запрещено |
| Суперпользователь | Все заметки | CRUD любых заметок |

Права проверяются сервером, включая прямые запросы к чужому ID. Владелец записи назначается сервером; переданный клиентом `owner` не меняет владельца. Сессия Django требует CSRF-токен для POST/PUT/DELETE. Пароли хранятся в виде хешей Django. Прежние общие записи при миграции сохраняются у отдельного неактивного пользователя с недоступным паролем.

## Резервное копирование SQLite

```powershell
.\.venv\Scripts\python.exe manage.py backup_database --output backups\notes-01.sqlite3
.\.venv\Scripts\python.exe manage.py restore_database backups\notes-01.sqlite3 --output backups\restored-01.sqlite3
```

SQLite Backup API создаёт согласованный снимок. Рядом сохраняется манифест SHA-256 для обнаружения повреждения файла. Восстановление проверяет контрольную сумму, `integrity_check` и внешние ключи. Файл назначения должен быть новым: существующая рабочая база не перезаписывается. SHA-256 не является шифрованием или доказательством подлинности; копии содержат данные и хеши паролей и должны храниться вне публичного репозитория.

Проверка: [backup-verification.json](backup-verification.json). Рабочая и восстановленная базы содержали по 3 заметки и 4 пользователя, `integrity_check=ok`, нарушений внешних ключей нет. Автотест отдельно проверяет восстановление записи после удаления из исходной БД и отказ при повреждённой копии.

Для переключения на восстановленную базу остановите приложение, сохраните отдельную копию текущего `db.sqlite3` и только затем замените его проверенным файлом. Автоматической замены рабочей базы команда не выполняет.

## PostgreSQL

Настройки поддерживают подключение через `DATABASE_URL`. Команды выше относятся к SQLite. Для PostgreSQL применяются штатные `pg_dump -Fc` и `pg_restore` в отдельную пустую базу; пароль передаётся через защищённый файл `.pgpass`, а не в командной строке. В этой работе фактическая проверка резервного копирования выполнена на SQLite; проверка PostgreSQL не заявляется.

## Управление пользователями

Демонстрационные учётные записи создаёт `python manage.py seed_demo`. Команда не меняет пароли существующих пользователей. Администратор создаётся отдельно через `python manage.py createsuperuser`. Встроенная панель доступна только при `ENABLE_ADMIN=true`; публичные тестовые аккаунты не имеют доступа к ней.
