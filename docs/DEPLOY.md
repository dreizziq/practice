# Публикация проекта

Публикация выполняется владельцем проекта. До неё публичные ссылки в отчёте и README остаются незаполненными. Локальный адрес не заменяет деплой.

## GitHub

Создайте публичный репозиторий. Загрузите исходники из корня проекта, включая скрытые `.github`, `.gitignore` и `.codeclimate.yml`. Не загружайте ZIP, `.venv`, `db.sqlite3`, `.env`, `staticfiles` и `tmp`.

Можно использовать GitHub Desktop или Git:

```powershell
git init -b main
git add .
git commit -m "Add notes API, browser interface and practice materials"
git remote add origin https://github.com/YOUR_ACCOUNT/YOUR_REPOSITORY.git
git push -u origin main
```

Замените URL своим. Если Git запросит имя автора, настройте настоящее имя и email. Последующие исправления и заполнение отчёта сохраняйте отдельными содержательными коммитами. Не подделывайте прошлую историю разработки.

## Render

Конфигурация соответствует [официальной инструкции Django](https://render.com/docs/deploy-django).

1. Подключите GitHub в Render, выберите **New → Blueprint**, затем репозиторий.
2. Проверьте ресурсы из `render.yaml`: web service и PostgreSQL, оба с планом `free`. Если этот план недоступен для аккаунта, самостоятельно выберите подходящий вариант.
3. Render создаёт `SECRET_KEY`, передаёт `DATABASE_URL` и имя хоста. `DEBUG=false`, админка выключена. Сборка собирает статику; запуск применяет миграции и добавляет одну демонстрационную заметку.
4. Дождитесь успешного запуска и сохраните URL вида `https://имя.onrender.com`.
5. Откройте сайт в инкогнито. Создайте заметку, измените, обновите страницу и удалите её. Проверьте `/api/note/`.

SQLite используется локально. Для хостинга настроен PostgreSQL: локальные файлы бесплатного Render не сохраняются между перезапусками.

По [условиям бесплатного тарифа](https://render.com/docs/free), сервис засыпает после 15 минут без запросов и может запускаться около минуты. Бесплатная PostgreSQL истекает через 30 дней. Перед проверкой убедитесь, что база ещё действует и сайт открывается.

## Проверка качества

В гайде указан Code Climate с оценкой A/B. [Официальная документация](https://docs.codeclimate.com/docs/overview) направляет новых пользователей в Qlty. Согласуйте с преподавателем, принимает ли он бейдж Qlty вместо Code Climate.

Подключите публичный репозиторий к согласованному сервису, дождитесь реального анализа и скопируйте ссылку на отчёт и URL изображения бейджа из интерфейса сервиса. В `submission.json` укажите сервис, результат, обе ссылки и факт согласования. Генератор вставит настоящий бейдж в README. Наличие `.codeclimate.yml` и успешные тесты сами по себе не подтверждают A/B.

## Заполнение отчёта и ссылок

1. Заполните `submission.json`: ФИО, группу, учебное заведение, руководителя, сроки, город, GitHub и деплой.
2. В `catalog_url` указан публичный каталог, где есть выбранная статья. Если преподаватель использует другой утверждённый каталог, замените ссылку на нужную.
3. Выполните:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-report.txt
.\.venv\Scripts\python.exe tools\build_submission.py
```

Команда обновит README, практическую часть отчёта, таблицу соответствия и PDF. Ссылки на GitHub будут указывать на конкретные файлы; ссылки на сайт — на форму, список и API. Проверьте `docs/BEFORE_SUBMISSION.md`.

В полученном гайде нет официального шаблона титульного листа, дневника или иных бланков. Титульный лист PDF имеет нейтральную структуру. Если учебное заведение требует свои бланки, перенесите практическую часть из `docs/REPORT.md` в этот шаблон. Вывод сверяйте со своим фактическим опытом.
